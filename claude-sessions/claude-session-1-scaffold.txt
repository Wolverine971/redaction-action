⏺ The project is set up and on GitHub: **https://github.com/Wolverine971/redaction-action** (private). The first CI run passed on GitHub.
  
  **What's in it**
  - **App:** Next.js 16.4 with React 19, TypeScript and Tailwind 4. The home page is a placeholder that shows whether the database is connected.
  - **Database:** a local Postgres database called `redaction_action`, running on your existing Homebrew Postgres 16. I used Drizzle as the database layer. The table definitions file (`src/db/schema.ts`) is empty and ready for your document tables. Migrations already work locally and in CI.
  - **Health check:** `/api/health` returns 200 when the database is up. When it's down, it returns 503 with the real reason, e.g. `database "x" does not exist`.
  - **Tests and CI:** Vitest has one test that hits the database. On every push, GitHub Actions runs lint, typecheck, migrations, tests and a production build against a fresh Postgres.
  - **Docs:** a README with setup steps, and a `CLAUDE.md` with the commands and conventions.
  
  To start: `pnpm dev`, then open http://localhost:3000.
  
  **Two defaults you can reverse:**
  - **Private repo.** I chose private because this is an interview submission. When you submit, you can make it public or add the reviewers as collaborators.
  - **Newer Next.js caching model.** This Next.js template turns it on by default. Pages are static unless marked otherwise, so any page that reads the database needs a loading boundary (`<Suspense>`). Without one, the build fails. I kept it because it's the current Next.js approach and it's noted in `CLAUDE.md`. If it gets in the way of the review flow, it's one line in `next.config.ts` to switch back to the old behavior.
  
  **Not tested:** I added a `docker-compose.yml` so reviewers without Postgres can run the app, but Docker isn't installed on this machine, so I couldn't try it.
  
  Ready for the document ingestion and review part whenever you are.
